# Drill #14 — 새의 비행 애니메이션

pico2d로 새 10마리가 좌우로 반복 비행하는 과제입니다. 수업에서 제공한
`bird_animation.png`의 실제 14프레임을 순서대로 재생합니다.

## 실행

Python이 설치된 Windows PowerShell에서 저장소 폴더를 열고 실행합니다.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

이미 pico2d 1.5.1이 설치된 Python 환경이라면 `python main.py`로 실행할 수 있습니다.
창 크기는 1280 × 720이며 Esc 또는 창 닫기 버튼으로 종료합니다.
이미지는 소스 파일 위치를 기준으로 읽으므로 다른 작업 폴더에서 실행해도 됩니다.

## 정확한 비행 애니메이션을 위한 구현 논리

1. **프레임 선택:** 원본은 918 × 506 이미지의 5열 × 3행 배열입니다.
   마지막 칸은 비어 있으므로 프레임 번호를 0~13으로 제한합니다.
   `divmod(int(frame), 5)`로 위에서부터의 행과 왼쪽부터의 열을 구합니다.
   이미지 크기가 격자 수로 나누어떨어지지 않으므로 각 경계는
   `column * image.w // 5`, `(column + 1) * image.w // 5`처럼 별도로 계산합니다.
   행도 같은 방식으로 계산하고, pico2d의 아래쪽 기준 좌표는 `image.h - bottom`으로 변환합니다.
2. **시간 기반 날갯짓:** 한 주기를 0.7초로 정해 14프레임을 초당 20프레임으로 재생합니다.
   `frame = (frame + 20 * dt) % 14`로 소수 부분까지 보존하고 그릴 때만 정수로 바꿉니다.
   렌더링 FPS가 바뀌어도 같은 시간 동안 같은 만큼 날갯짓이 진행됩니다.
3. **시간 기반 수평 비행:** `perf_counter()`로 프레임 시작 사이의 실제 경과 시간 `dt`를 구합니다.
   이동 거리는 `speed * dt`입니다. 모든 새는 높이를 유지하며, 각 속도는 120~200픽셀/초입니다.
   목표 60 FPS에 남는 시간만 대기하며, 렌더링에 걸린 시간을 다음 `dt`에 포함합니다.
4. **경계 반사:** 그림 크기가 110 × 101이므로 중심의 수평 범위는 55~1225입니다.
   이 구간 길이를 `L = 1170`이라 할 때 왕복 경로의 길이는 `2L`입니다.
   `travel = (travel + speed * dt) % (2L)`로 갱신한 뒤, 전반부는 오른쪽,
   후반부는 왼쪽으로 접어 실제 위치를 계산합니다. 큰 `dt`가 들어와 여러 경계를
   통과해도 이동 거리를 버리지 않고 화면 안의 올바른 위치와 방향으로 돌아옵니다.
   오른쪽 경계에서는 즉시 왼쪽을, 왼쪽 경계에서는 즉시 오른쪽을 향합니다.
5. **방향 표현:** 원본 새는 오른쪽을 향합니다. 왼쪽 이동 중에는
   `clip_composite_draw(..., flip='h', ...)`로 수평 반전합니다.
   반사할 때 프레임을 초기화하지 않아 날갯짓이 끊기지 않습니다.
6. **10마리 독립 상태:** 각 새는 위치, 방향, 속도, 왕복 경로 위치, 애니메이션 프레임을
   따로 보관합니다. 시작 위치·속도·프레임 위상을 다르게 하여 움직임이 완전히 겹치지 않게 합니다.
   `Random(14)`로 초기 구성을 재현할 수 있고, 이미지는 한 번만 읽어 10마리가 공유합니다.
7. **종료와 경로:** Esc와 창 닫기를 처리하고 `finally`에서 자원을 정리합니다.
   SDL 렌더러를 닫기 전에 새들과 공유 이미지 참조를 해제합니다.

## 파일 구성

- `main.py`: 창, 이벤트, 실제 경과 시간 계산, 렌더링 루프, 종료 처리
- `bird.py`: 14프레임 애니메이션, 왕복 이동, 방향 반전
- `flock.py`: 새 10마리 생성, 이미지 공유, 개체별 초기 상태
- `settings.py`: 화면 크기, 목표 FPS, 새 개수
- `ASSETS.md`: 과제 원본 이미지 출처

`git log --reverse --oneline`으로 진행 순서를, `git log -1 --format=full`로 최종 설명을 볼 수 있습니다.

사용자 요청에 따라 실행 테스트·화면 자동 검증은 생략했습니다.
Python 문법과 Git 공백 오류만 확인합니다. 직접 실행할 때 새 10마리, 좌우 반복 비행,
날갯짓 연결, 진행 방향과 부리 방향의 일치 여부를 확인하면 됩니다.
